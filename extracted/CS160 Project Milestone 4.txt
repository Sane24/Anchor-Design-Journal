Checked whether tasks land
on the correct calendar day
across different user
timezones
Bug found: sample task dates
are generated in UTC, while
This Week keys days using
local time. For users in UTC+
timezones (e.g., Europe,
Asia), tasks appeared on the
wrong calendar day. The bug
was not caught earlier
because all testing had been
done in US timezones, where
the UTC/local mismatch
doesn't cross a day boundary.
Identified as an open bug, not
yet fixed. Planned fix for next
iteration: generate day-offset
dates using local date
formatting (matching the
same toKey function This
Week already uses) instead of
UTC, so date generation and
date lookup use a consistent
timezone basis.
